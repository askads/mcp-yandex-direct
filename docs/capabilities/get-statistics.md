# Яндекс Директ: Статистика — MCP-инструмент (tool)

**MCP-инструмент (tool) для Яндекс Директа:** Запрашивает отчёт по эффективности через сервис Reports Яндекс Директа.

Техническое имя: `get_statistics`

## Какую задачу решает

> Я хочу посмотреть статистику.

Запрашивает отчёт по эффективности через сервис Reports Яндекс Директа.

## Когда использовать

Используйте эту возможность, когда нужен результат «Статистика» без ручной работы в интерфейсе Яндекс Директа. Операция выполняется только по вызову из AI-приложения.

## Что нужно передать

- `reportType` — **необязательно**. Тип отчёта. По умолчанию CAMPAIGN_PERFORMANCE_REPORT; CUSTOM_REPORT — произвольные разрезы (устройства, пол и возраст, регионы, площадки).
- `dateRangeType` — **необязательно**. Предустановленный период. Если заданы dateFrom/dateTo, подставляется CUSTOM_DATE.
- `dateFrom` — **необязательно**. Дата начала YYYY-MM-DD (обязательна для CUSTOM_DATE).
- `dateTo` — **необязательно**. Дата окончания YYYY-MM-DD (обязательна для CUSTOM_DATE).
- `fieldNames` — **необязательно**. Колонки отчёта (должны быть допустимы для его типа). Сверх базовых метрик: Conversions, ConversionRate, CostPerConversion, Revenue, Profit, GoalsRoi.
- `campaignIds` — **необязательно**. Ограничить отчёт этими id кампаний.
- `filters` — **необязательно**. Произвольные условия SelectionCriteria.Filter (`field`, `operator`, `values`), складываются с campaignIds по И.
- `goals` — **необязательно**. Id целей Метрики (до 10): конверсии и доход по конкретным целям вместо суммы по всем.
- `attributionModels` — **необязательно**. Модели атрибуции FCCD/LC/LSCCD/AUTO для конверсий по целям из `goals`; без `goals` не применяются. По умолчанию LC.
- `includeVat` — **необязательно**. Включать ли НДС в расход. По умолчанию true.
- `compareTo` — **необязательно**. `{dateFrom, dateTo}` — период для сравнения с текущим (текущий тогда задаётся явными `dateFrom`/`dateTo`). Запускает две задачи Reports и возвращает строки, сопоставленные по разрезам отчёта (по id, а не по названию, если id запрошен), с `current`, `previous`, `delta`, `deltaPct`. Не для `SEARCH_QUERY_PERFORMANCE_REPORT` и не с `Date`/`Week`/`Month`/`Quarter`/`Year` в `fieldNames`.
- `sortBy` — **необязательно**. Метрика для ранжирования строк детализации. По умолчанию Cost.
- `order` — **необязательно**. Порядок сортировки строк детализации. По умолчанию desc.
- `topN` — **необязательно**. Максимум строк детализации в сводке (на сервере ограничено 100). По умолчанию 50.
- `minCost` — **необязательно**. Включать в детализацию только строки с Cost >= этого значения.
- `queryContains` — **необязательно**. Включать только строки, где запрос или условие содержит эту подстроку (без учёта регистра).
- `zeroClicksOnly` — **необязательно**. Включать в детализацию только строки с 0 кликов.
- `zeroConversionsOnly` — **необязательно**. Только строки с clicks>0 и 0 конверсий (нужно Conversions в fieldNames).

## Что вернёт

Возвращает компактный JSON-ответ исходного API или понятную ошибку MCP-инструмента. Точный состав полей зависит от операции и описан в техническом справочнике.

С `compareTo` — JSON сравнения: `matchKey` (по каким колонкам сопоставлены строки), `counts` (сколько строк есть в обоих периодах и в одном), `totals` (суммы показов, кликов, расхода, конверсий, дохода — отношения вроде CTR в итогах не пересчитываются), `rows` с `current` / `previous` / `delta` / `deltaPct` и пометкой `onlyIn` для строк одного периода, `tail` для строк сверх `topN`. Вклад факторов (показы × CTR × CPC) инструмент не считает: каждое число — значение Яндекса или разность двух значений.

## Что изменится в Яндекс Директе

Инструмент только читает данные или состояние подключения и не изменяет их.

## Пример запроса

> Посмотреть статистику в Яндекс Директе. Если не хватает обязательных идентификаторов, сначала уточни их.

## Возможные ошибки и ограничения

По умолчанию отчёт АГРЕГИРОВАН за весь период (одна строка на объект) — добавлять "Date" в fieldNames только для динамики по дням или вопросов о трендах. Почасовой статистики в Reports нет: минимум — сутки, внутридневную динамику дают только повторные снимки TODAY. Готового ROAS нет — считать Revenue / Cost; GoalsRoi — это ROI ((Revenue − Cost) / Cost), не ROAS. Revenue, Profit, GoalsRoi и конверсии заполняются только по целям Метрики с ценностью. ALL_TIME без фильтра по кампаниям отклоняется для отчётов SEARCH_QUERY/CRITERIA: нужно передать campaignIds или ограниченный период. SEARCH_QUERY_PERFORMANCE_REPORT возвращает не сырые строки, а ВЫЧИСЛЕННУЮ СВОДКУ (итоги по ВСЕМ строкам + детализация top-N + свёртка хвоста + количество строк без кликов и без конверсий); её форму задают sortBy/topN/minCost/queryContains/zeroClicksOnly/zeroConversionsOnly, а для подсчётов по конверсиям нужно добавить Conversions в fieldNames. Остальные типы отчётов возвращают строки, разделённые табуляцией (без заголовка).

Доступ также зависит от прав токена, квот и ограничений исходного API.
